# i18n — Interface languages

Calc Rush ships in 6 languages: `fr` (source), `en` (US), `es`, `it`, `pt-BR`, `de`. Library: `i18next` + `react-i18next` (no `i18next-browser-languagedetector`: it would cache the detected language and freeze `auto`).

## Language preference

- Type `LocalePreference = 'auto' | Locale`, default `'auto'`, stored in `localStorage` under `calc-rush:locale` (`LOCALE_STORAGE_KEY`). No network call, no backend storage.
- `'auto'` is never persisted as a concrete language, so it keeps following the device.
- `resolveLocale(preference, navigator.languages)` (`src/i18n/locale.ts`): prefix matching, first supported entry wins (`es-MX` → `es`, `pt-PT` → `pt-BR`, `en-GB` → `en`), fallback `en`.
- `useLocalePreference` (`src/hooks/`) reads/writes the preference, calls `i18n.changeLanguage` and sets `document.documentElement.lang`. The language picker is available to everyone, logged in or not: the language card in `SettingsPage` (the rest of the page still requires login) and a compact `<select>` in `Footer`. A `storage` event for the key (other tab) re-applies the stored preference. Stripe checkout receives the active `i18n.language`.

## File layout (`src/i18n/`)

| File                             | Role                                                                                                                                |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `locale.ts`                      | Pure: `LOCALES`, `LOCALE_NAMES`, `Locale`, `LocalePreference`, `FALLBACK_LOCALE`, `isLocale`, `isLocalePreference`, `resolveLocale` |
| `index.ts`                       | Initializes i18next (all locales bundled), `applyLocale`, `readLocalePreference`                                                    |
| `i18next.d.ts`                   | `CustomTypeOptions`: `t('…')` keys are typed from `typeof fr`                                                                       |
| `locales/fr.ts`                  | Source of truth, grouped by screen/feature (`home.*`, `lobby.*`, `levels.short.CP`, …)                                              |
| `locales/{en,es,it,pt-BR,de}.ts` | Each `satisfies Translation`: a missing or extra key fails `tsc`                                                                    |

Plurals use i18next suffixes (`_one` / `_other`); interpolation uses `{{var}}`. Label tables that used to be constants (grades, levels, quests, titles, icons, rarity, API/WS errors, plans) are keys; their resolvers in `src/lib/` take `t` as a parameter to stay pure (`resolveLevelLabel(level, t, 'short' | 'long')`, `resolveGradeLabel`, `resolveQuestLabel`, …).

## Adding a key

1. Add it to `locales/fr.ts` (French first).
2. Translate it into `en`, `es`, `it`, `pt-BR`, `de`. `npx tsc -b` fails until all 5 have it.
3. Use it with `const { t } = useTranslation(); t('group.key')`.

Tone: friendly, addressed to a child (fr « tu » → es « tú », it « tu », pt-BR « você », de « du », en plain « you »). Keep copy short; it must fit the same buttons and badges. English is US English, Portuguese is Brazilian.

## Adding a language

1. Add the code to `LOCALES` and its native name to `LOCALE_NAMES` in `locale.ts`.
2. Create `locales/<code>.ts` with `satisfies Translation` and register it in `index.ts`.
3. Translate everything (including `levels`, legal pages, the legal notice). Check the Stripe locale list on the backend.

## Vocabulary

- School levels keep stable IDs (`CP` … `TROISIEME`); only labels are localized, in two forms: `short` (≤ 4 characters, avatar badge in `PlayerAvatar` / `PlayerLevel`) and `long` (header menu, level selector, grade guide, profile).
- English calls the XP tier « rank » (Bronze → Diamond) and school levels « Grade N ». The profile history column is « Place » to avoid clashing with the XP rank.

## Formatting

Locale-bound formatting follows `i18n.language`: `lib/mathFormat`, `lib/money`, `lib/date`.

## Legal pages

CGV, privacy, legal notice and terms are translated. Non-French versions show `LegalTranslationNotice` (translated line: only the French version is legally binding). Identity data (name, email, SIRET, address) is shared in `src/lib/legalIdentity.ts` and not translated.

## Parental gate

The questions are universal (no language- or country-specific culture), see `src/lib/parentalGate.ts`.

## Stripe

`createCheckoutSession(fetch, plan, locale)` sends `{ plan, locale }` with the resolved locale (preference, or `navigator.languages` when `auto`). The backend accepts `fr/en/es/it/pt-BR/de` since back 0.27.0; the front can ship before it, an unknown field is ignored.

## Tests

`src/test-setup.ts` forces `fr` and resets to `fr` after each test, so existing specs querying French text keep passing. In a test, call `act(() => { void i18n.changeLanguage('en'); })` (or before render) to switch. `locales.spec.ts` checks that no value is empty in any locale.

## Out of scope

Push notifications and backend-sent text, multilingual SEO (per-language URLs, `hreflang`), store listings, non-EUR currencies. The static social/OG assets (`SocialAssets`) stay French.
